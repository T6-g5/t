## 二、Rules（规则）

### 2.1 什么是 Rules

Rules 是 AI 编程工具的行为约束配置，用于规范 AI 的输出格式、内容范围和操作权限。通过设置 Rules，可以确保 AI 生成的代码和文档符合项目规范，避免不符合要求的输出。

### 2.2 本项目建议设置的 Rules

以下规则必须写入当前 AI 工具的 Rules 配置中：

```
- 所有功能必须以 docs/00-赛题要求-A3.md 为依据，不得编造赛题要求。
- 不确定的信息必须标注"不确定"或"赛题原文未明确说明"。
- 重要产物优先保存为文件，不只在聊天窗口输出。
- 不得删除用户已有文件，除非用户明确要求。
- 每完成一个阶段，都要更新 README 或 docs 中的对应说明。
- 代码必须包含可运行命令、环境变量示例和测试说明。
- A3 核心能力必须围绕学生画像、课程知识库、RAG 防幻觉、多智能体资源生成、学习效果评估。
- 生成代码后必须运行或说明如何运行测试。
- 项目必须使用 Git 管理，不提交 API Key、密钥、账号密码或大模型服务凭证。
```

### 2.3 Rules 使用方式

将上述规则复制到 AI 工具的 Rules 配置区域，确保每次对话都生效。如工具不支持 Rules 配置，则在每次对话开始时粘贴规则作为系统提示。

## 三、Skills（技能）

### 3.1 什么是 Skills

Skills 是 AI 编程工具的扩展能力模块，通过封装特定领域的知识和操作流程，使 AI 能够更高效地完成特定任务。Skills 通常包含专业知识、操作步骤和输出规范。

### 3.2 本项目建议使用的 Skills

| Skill 名称 | 使用阶段 | 用途说明 |
|-----------|---------|---------|
| **赛题解析 skill** | 第 0 步 | 提取比赛要求，整理为结构化文档 |
| **PRD/产品经理 skill** | 第 3 步 | 生成产品需求文档，定义功能模块和交互流程 |
| **Pencil 原型设计 skill** | 第 4-5 步 | 生成低保真和高保真原型，输出 .pen 文件 |
| **前端开发 skill** | 第 7、10 步 | 实现学生端、教师端和后台管理页面 |
| **后端开发 skill** | 第 7-10 步 | 实现 API 接口、数据库设计和业务逻辑 |
| **RAG 知识库 skill** | 第 8 步 | 实现课程知识库构建、向量检索和引用来源追踪 |
| **多智能体 skill** | 第 9 步 | 实现学生画像智能体、学习规划智能体、资源生成智能体、效果评估智能体、推荐智能体 |
| **测试验收 skill** | 第 11-12 步 | 生成测试用例，执行测试并修复问题 |
| **文档/PPT skill** | 第 13 步 | 生成部署手册、演示 PPT 和视频脚本 |
| **Git 管理 skill** | 每个阶段完成后 | 提交代码版本，管理分支和合并 |

### 3.3 Skills 使用时机

```
阶段 0：赛题解析 skill → 提取赛题要求
阶段 1：需求分析
阶段 2：系统设计
阶段 3：PRD/产品经理 skill → 生成产品需求文档
阶段 4：Pencil 原型设计 skill → 生成低保真原型
阶段 5：Pencil 原型设计 skill → 生成高保真原型
阶段 6：技术选型
阶段 7：前端开发 skill + 后端开发 skill → 核心功能实现
阶段 8：RAG 知识库 skill → 课程知识库建设
阶段 9：多智能体 skill → 智能体系统开发
阶段 10：前端开发 skill + 后端开发 skill → 功能完善
阶段 11：测试验收 skill → 单元测试和集成测试
阶段 12：测试验收 skill → 系统测试和修复
阶段 13：文档/PPT skill → 生成交付文档
```

## 四、MCP（Model Context Protocol）

### 4.1 什么是 MCP

MCP（Model Context Protocol）是 AI 编程工具与外部系统交互的协议，允许 AI 通过工具调用的方式访问文件系统、数据库、API、终端等外部资源。通过 MCP，AI 可以读取/写入文件、执行命令、查询数据，实现更强大的自动化能力。

### 4.2 本项目建议配置的 MCP

| MCP 名称 | 用途说明 |
|---------|---------|
| **Pencil MCP** | 读取和修改 .pen 原型文件，实现原型设计和导出 |
| **文件系统 MCP** | 读取、创建、修改项目文件，管理代码和文档 |
| **浏览器/网页抓取 MCP** | 读取赛题网页和官方文档，获取最新信息 |
| **Git/终端 MCP** | 执行 git 命令（commit、push、branch）、npm 命令（install、run）、python 命令、测试命令 |
| **SQLite/数据库 MCP** | 检查本地数据表结构和测试数据，验证数据库操作 |
| **API 测试 MCP** | 验证后端接口返回是否符合 PRD 定义，确保接口正确性 |

### 4.3 MCP 配置优先级

```
1. 文件系统 MCP（必备）
2. Git/终端 MCP（必备）
3. SQLite/数据库 MCP（核心功能开发阶段必备）
4. API 测试 MCP（接口开发阶段必备）
5. Pencil MCP（原型设计阶段必备）
6. 浏览器/网页抓取 MCP（赛题解析阶段必备）
```

## 五、替代方案：无 Skills/MCP 支持时的处理

如果使用的 AI 编程工具不支持 Skills 或 MCP，可以通过以下方式替代：

### 5.1 固定提示词替代 Skills

**创建固定提示词文件**：`docs/ai-prompts/`

#### 提示词文件结构：

```
docs/ai-prompts/
├── 00-赛题解析.md          # 赛题解析阶段使用
├── 03-PRD生成.md           # PRD 生成阶段使用
├── 04-05-原型设计.md       # 原型设计阶段使用
├── 07-前端开发.md          # 前端开发阶段使用
├── 07-后端开发.md          # 后端开发阶段使用
├── 08-RAG知识库.md         # RAG 开发阶段使用
├── 09-多智能体开发.md       # 多智能体开发阶段使用
├── 11-12-测试验收.md       # 测试验收阶段使用
└── 13-文档生成.md          # 文档生成阶段使用
```

#### 提示词模板示例（以 RAG 知识库为例）：

```
# RAG 知识库开发提示词

## 任务目标
实现课程知识库的构建和查询功能，支持 RAG 防幻觉机制。

## 参考文档
- docs/00-赛题要求-A3.md（赛题要求）
- docs/01-系统架构设计.md（系统架构）

## 核心要求
1. 构建至少一门完整高校专业课程的知识库
2. 实现向量检索功能
3. 支持引用来源追踪
4. 实现防幻觉机制
5. 代码包含环境变量配置和测试说明

## 输出规范
- 代码保存到 src/rag/ 目录
- 提供详细的运行说明
- 输出测试用例
```

### 5.2 文档规范替代 MCP

**无法使用 MCP 时的操作流程**：

| MCP 功能 | 替代方式 |
|---------|---------|
| 文件读写 | 用户手动创建文件，将内容粘贴到聊天窗口供 AI 修改 |
| 命令执行 | AI 提供命令，用户手动在终端执行并反馈结果 |
| 数据库操作 | AI 提供 SQL 语句，用户手动执行并反馈结果 |
| API 测试 | AI 提供测试命令或代码，用户手动执行并反馈结果 |
| 原型设计 | 使用 Pencil Desktop 客户端手动设计 |

### 5.3 手动操作规范

当无法使用 MCP 自动操作时，遵循以下流程：

1. **AI 输出**：给出操作指令和代码片段
2. **用户执行**：在本地环境执行命令或创建文件
3. **结果反馈**：将执行结果或文件内容粘贴回聊天窗口
4. **AI 分析**：根据反馈继续指导下一步操作

## 六、Rules 配置文件（可选）

### 6.1 创建项目级 Rules 文件

在项目根目录创建规则文件，方便不同工具加载：

**文件路径**：`.cursorrules`（适用于 Cursor 编辑器）

```
# A3 项目 Rules - 中国软件杯
# 来源：docs/00-AI工具使用规范.md

1. 所有功能必须以 docs/00-赛题要求-A3.md 为依据，不得编造赛题要求。
2. 不确定的信息必须标注"不确定"或"赛题原文未明确说明"。
3. 重要产物优先保存为文件，不只在聊天窗口输出。
4. 不得删除用户已有文件，除非用户明确要求。
5. 每完成一个阶段，都要更新 README 或 docs 中的对应说明。
6. 代码必须包含可运行命令、环境变量示例和测试说明。
7. A3 核心能力必须围绕学生画像、课程知识库、RAG 防幻觉、多智能体资源生成、学习效果评估。
8. 生成代码后必须运行或说明如何运行测试。
9. 项目必须使用 Git 管理，不提交 API Key、密钥、账号密码或大模型服务凭证。
```

### 6.2 其他工具配置

根据使用的 AI 工具，将规则配置到对应位置：

- **Trae CN**：在设置中配置系统提示词
- **Claude Code**：使用 `---` 分隔符设置系统提示
- **VS Code Copilot**：在 settings.json 中配置 `github.copilot.systemPrompt`

## 七、核心能力检查清单

在开发过程中，确保覆盖以下核心能力：

| 核心能力 | 检查项 | 状态 |
|---------|--------|------|
| **学生画像** | 对话式构建、≥6个维度、动态更新 | ☐ |
| **课程知识库** | 至少一门完整课程、向量检索、引用追踪 | ☐ |
| **RAG 防幻觉** | 内容校验、来源标注、事实性检查 | ☐ |
| **多智能体资源生成** | ≥5种资源类型、多角色协作 | ☐ |
| **学习效果评估** | 多维度评估、动态调整策略 | ☐ |
